기업 혜택 찾기 사이트 사용법

[파일 구성]
index.html        사이트 페이지 (더블클릭으로 열거나 웹서버에 올리면 됨)
app.js            매칭 로직. 혜택검색사이트_프롬프트.txt 의 매칭 규칙을 그대로 코드로 옮긴 것
data/benefits.js  공고 데이터. 수집기 출력으로 교체하는 파일
page.html         claude.ai 아티팩트 게시용 본문 (index.html과 내용 동일, 문서 틀만 없음)

[동작 방식]
1. 사용자가 사업자 유형, 업력, 업종, 연매출, 상시근로자, 소재지, 체납 여부를 입력
2. app.js 가 data/benefits.js 의 공고 하나하나를 8개 조건으로 판정
   신청 기간 / 사업자 유형 / 업력 / 업종 / 매출 / 고용 / 소재지 / 세금 체납
   하나라도 불일치 → 제외
   정보 부족 → 포함하되 "확인 필요" 표시 (점선 카드)
3. 확실한 매칭 → 확인 필요 순, 각각 마감 임박순으로 표시. 상시 제도는 맨 뒤
4. 맞는 공고가 없으면 카드 없이 "조건에 맞는 혜택이 없습니다" 한 줄만 표시

[공고 데이터 넣는 법]
data/benefits.js 의 window.BENEFITS 배열을 수집기 출력으로 교체한다.
필드 정의는 혜택검색사이트_프롬프트.txt 의 [입력] 2번과 같다.
숫자 조건(상시근로자 N인 미만 등)은 min_/max_ 필드에 숫자로, 텍스트로만 있는 조건은 *_text 필드에 원문을 넣는다.
*_text 필드만 있으면 판정하지 않고 "확인 필요"로 포함된다.

업종 코드(target_ksic_codes)는 한국표준산업분류 코드 또는 접두어 배열이다.
  예: ["56"]     → 음식점 및 주점업 전체
      ["56111"]  → 한식 일반 음식점업만
      null       → 업종 제한 없음

지역(target_districts)은 "시/도 시/군/구" 형식이다. 예: ["서울특별시 종로구"]

[업종 선택]
사용자는 대분류(예: J 정보통신업 전체), 중분류(예: 62 컴퓨터 프로그래밍), 세부 코드(5자리) 중 하나로 입력한다.
대분류로 선택했는데 공고가 그 안의 일부 중분류만 대상으로 하면 "확인 필요"로 표시된다.
세부 코드를 입력하면 확정 판정된다.

[주의]
- 조회일은 브라우저의 오늘 날짜다. 마감이 지난 공고는 자동으로 빠진다.
- 입력값은 브라우저에 저장되어 다음에 열 때 복원된다. "초기화"를 누르면 지워진다.
- 사이트는 공고를 직접 수집하지 않는다. 수집은 별도 시스템이 하고, 이 사이트는 수집된 데이터를 판정해서 보여주는 역할만 한다.
